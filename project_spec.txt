Fish Cart - Project Specification

1. PROJECT OVERVIEW
Project Title: Fish Cart - Hyperlocal Seafood Delivery System
Tech Stack: MERN (MongoDB, Express, React, Node.js)
Type: Hyperlocal E-Commerce / On-Demand Logistics

2. PROBLEM STATEMENT
- Wastage: Vendors over-purchase and lose money if fish is unsold.
- Inconvenience: Customers must visit wet markets early to get fresh stock.
- Processing hassle: Cleaning/cutting at home is messy and time-consuming.
- Uncertainty: Customers do not know current availability before visiting market.

3. PROPOSED SOLUTION
- Daily fresh inventory managed by admin after procurement.
- Shop open/close control to enforce order window.
- Preparation selection per item (Whole, Cleaned, Curry Piece, Fry Cut).
- Role-based operations for Customer, Admin, and Delivery Partner.
- Shift-based partner workflow and COD cash-transfer verification.

4. USER ROLES & PERMISSIONS
A. Customer
- Register/login.
- View daily catch and filter by category.
- Choose preparation option and quantity.
- Place orders.
- View order status.
- Cancel order only when status is Pending.

B. Admin
- Secure login to admin dashboard.
- Manage products (add/edit/delete, price/stock/image, cut options, visibility).
- Control shop status (open/close) and default cleaning fee.
- View orders, filter by area/status/date.
- Assign delivery partners.
- Update order status (except cancelled order updates are blocked).
- Packing list operations with per-product mark packed behavior.
- Verify partner cash transfer records.

C. Delivery Partner
- Login with mobile-first dashboard.
- View assigned deliveries only when status is Packed/Out for Delivery/Delivered.
- Reorder pending delivery sequence.
- Update delivery status (Out for Delivery -> Delivered).
- Shift controls:
  - Cannot turn ON shift when no deliveries to do.
  - Cannot turn OFF shift until all deliveries are done.
- Mark COD amount as transferred to admin after shift completion.

5. DATABASE STRUCTURE (HIGH LEVEL)
A. User
- name, email, password, phone, address
- role: user/admin/partner
- areaOfService, approval status, block status, activity timestamp

B. Product
- fishName, price, stockQuantity, imageURL
- category: Sea Fish/Shellfish/River Fish
- status: Available/Sold Out
- cutOptions: array (Whole (Uncleaned), Cleaned, Curry Piece, Fry Cut)
- cleaningFee, isActive

C. Order
- userId, items, totalAmount, paymentMethod (COD/PREPAID)
- status: Pending/Packed/Out for Delivery/Delivered/Cancelled
- assignedPartnerId, runOrder, areaId
- deliveryOverride fields (name/phone/address/area)
- Item fields include fishName, qty, preparation, packed (boolean for packing-list item-level packing)

D. Area
- name, areaCode, deliveryFee

E. ShopStatus
- isOpen, cleaningFee

F. CashTransfer
- partnerId, date (YYYY-MM-DD), amount
- status: pending/verified
- transferredAt, verifiedBy, verifiedAt

6. BUSINESS RULES
- Cancelled order behavior:
  - Customer can cancel only Pending order.
  - Product stock is restored on cancel.
  - Cancelled orders are excluded from partner assigned list and key admin metrics/packing queue.
  - Cancelled order status cannot be updated further.
- Payment display for cancelled orders:
  - COD cancelled: show no charge message.
  - PREPAID cancelled: show refunded amount label.
- Packing list:
  - "Mark Packed" marks only selected product line items in relevant orders.
  - Order moves to Packed only when all items in that order are marked packed.
- Partner cash transfer:
  - Transfer amount is COD delivered for current shift/day, not historical cumulative COD.
  - After partner marks transfer, transfer panel is hidden.

7. FEATURE WORKFLOW (USER JOURNEY)
1) Admin updates stock and opens shop.
2) Customer browses products, selects preparation/qty, places order.
3) Admin prepares packing list and marks product items packed.
4) Admin assigns packed orders to partner.
5) Partner starts shift, delivers route, updates statuses.
6) On shift completion, partner marks COD transfer.
7) Admin verifies transfer in partner overview.

8. API ENDPOINTS (KEY)
Auth:
- POST /api/auth/register
- POST /api/auth/login
- GET /api/auth/me

Products:
- GET /api/products
- POST /api/products (admin)
- PUT /api/products/:id (admin)
- DELETE /api/products/:id (admin)

Orders:
- POST /api/orders
- GET /api/orders/myorders
- GET /api/orders/admin (admin)
- PUT /api/orders/:id/status
- PUT /api/orders/:id/cancel (customer, pending only)
- GET /api/orders/assigned (partner; only Packed/Out for Delivery/Delivered)
- PUT /api/orders/assigned/reorder (partner)
- PUT /api/orders/admin/mark-product-packed (admin; item-level packing)

Cash transfer:
- GET /api/orders/partner/cash-transfer
- POST /api/orders/partner/cash-transferred

Admin partner ops:
- GET /api/admin/partners/overview
- PUT /api/admin/assign-partner

9. DEPLOYMENT & CORS NOTES
- Frontend should use VITE_API_URL in production.
- Backend CORS uses FRONTEND_URL and can allow comma-separated origins.
- For Vercel frontend, set FRONTEND_URL=https://fishcart.vercel.app on backend.
